# 今回用意しているアプリケーションについて

---

## アプリケーション概要

- Sakuravel というサービスです
- Twitter / X ライクな短文投稿 SNS（マイクロブログ）アプリケーション
  - 短文投稿の作成・閲覧
  - 他ユーザーのフォロー
  - 投稿への「いいね」「リポスト」
  - キーワード検索
  - 通知の受信
  - プロフィール訪問履歴（足跡）の確認
  - トレンド投稿の閲覧

---

# アプリケーションの構成について


## 技術スタック

**バックエンド**
- Go 1.25 / 標準ライブラリ `net/http`
- MariaDB 10.11

**インフラ**
- Docker / Docker Compose
- nginx（TLS 終端 / リバースプロキシ）

---

## システム構成図

※アプリの仕様理解のためにフロントエンドも用意していますが、
今回の作業対象ではありません！
```
                ┌─────────────────────┐
                │      Browser        │
                └──────────┬──────────┘
                           │ HTTPS / HTTP2
                ┌──────────▼──────────┐
                │ nginx  :443         │  TLS終端・単一オリジン化
                └───────┬───┬─────────┘
                   /    │   │   /backend/*
        ┌───────────────▼┐ ┌▼───────────────┐
        │ Frontend       │ │ Backend API    │
        │ :3000          │ │ Go / :8080     │
        └────────────────┘ └──────┬─────────┘
                        ┌─────────▼─────────┐
                        │ MariaDB           │
                        └───────────────────┘
```

フロントとAPIを同一オリジンに載せているため CORS が不要。
nginx のアクセスログ（`upstream=`）でエンドポイント別の処理時間を継続的に見られる。

# 既存のデプロイ方法

- 手順
  1. コードを修正します
  2. 動作確認をします
    - `backend/`に`docker-compose.yml`があるのでこれを利用します
  3. Dockerfileをもとにイメージをビルド & コンテナレジストリへPush
  4. VM側でPullして反映
- ということでイメージのビルドとPush方法は別資料に続く・・・
